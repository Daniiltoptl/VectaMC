# Изменения VectaMC

## 2026-10-28 · Начало разработки

- Импортирован SteelMC `65cd7ab416bb2bbe04d4aca3b6d04b1d939d5a8d`
  с историей и лицензией; цель — Minecraft Java 26.3.
- Оформлены README, план этапов и сведения о происхождении проекта.
- CI адаптирован к VectaMC: сборка/тесты Linux и Windows, Rustfmt, Clippy,
  проверки Python-инструментов. Удалены workflows публикации и ботов SteelMC.
- Подготовка ванильного эталона заменена на Python + Vineflower без Gradle:
  проверка загрузок, точная версия из Cargo.toml, локальный provenance-файл.
- Базовый `cargo check -p steel-core --locked` прошёл на Windows.

Это начальный этап разработки, а не релиз с полной ванильной совместимостью.

## 2026-10-28 · Пузырёк опыта: бросок из рук

- Добавлены `ExperienceBottleItem` и `ThrownExperienceBottleEntity`, регистрация
  через существующие генераторы поведения и фабрик сущностей.
- Реализованы бросок из любой руки, расход в выживании, сохранение предмета
  в креативе, статистика использования, звук и полёт с параметрами 26.3.
- При попадании создаются частицы и 3–11 единиц опыта; звук разбивания
  учитывает Silent, а сферы разлетаются от поверхности или против движения
  пузырька при попадании в сущность. Сам пузырёк удаляется, прямой урон не наносится.
- Добавлен направленный спавн сфер опыта, включая смещение от точки удара
  и поиск свободного места при пересечении блока. Начальная скорость использует
  вычисления double, как в ванильном конструкторе.
- Сохраняются владелец и компоненты отображаемого предмета.
- Добавлены 6 регрессионных тестов: руки/режимы/размеры стака, все грани блока,
  попадание в сущность, NBT, направление сфер и освобождение от стены.
- Пройдена группа `cargo test --locked -p steel-core --lib experience`:
  21 тест, включая существующие проверки опыта.

Эталон: локальные `ExperienceBottleItem.java`, `ThrownExperienceBottle.java`,
`ExperienceOrb.java` и `Vec3.java` из официального сервера 26.3. Контрольная
сумма сервера указана в локальном `minecraft-src/.vecta-reference.json`.
Раздатчики требуют общей диспетчеризации `ProjectileItem` и в этот этап не входят.
Проверка настоящим клиентом пока не выполнена.

## 2026-10-28 · Переименование в VectaMC

- Все 10 Rust-пакетов и их каталоги переименованы: `vecta`, `vecta-core`,
  `vecta-protocol` и остальные `vecta-*`. Исполняемый файл — `vecta` / `vecta.exe`.
- Обновлены импорты, генераторы, Cargo.lock, имена внутренних типов и
  пространства имён собственных возможностей сервера на `vecta:`.
- Бренд клиента, стартовые сообщения, MOTD, заголовок TAB и ссылки сервера
  используют VectaMC. Ссылки на Discord SteelMC убраны из настроек VectaMC.
- Обновлены Docker, Compose, Nix, схемы конфигурации и инструкции сборки.
  Compose собирает локальный образ `vectamc:local`; опубликованный образ пока
  не заявляется.
- Сохранены лицензия, авторство, upstream Git и оригинальный README.
  Название ванильного предмета `flint_and_steel` и исходные значения эталонных
  тестовых данных не переименовываются.

Старые команды проверки выше относятся к состоянию до переименования.
Текущий пример: `cargo test --locked -p vecta-core --lib experience`.

Проверено на Windows: `cargo check --locked --workspace`, форматирование,
4 Python-теста и полный `cargo test --locked --workspace` — **3717 успешно,
18 пропущены, 0 ошибок**, включая тесты документации. Извлечённые данные
Minecraft и версии/контрольные суммы внешних зависимостей при переименовании
не изменялись. Иконка VectaMC создана из `assets/vecta-icon.svg`;
для повторного экспорта PNG есть `scripts/render_favicon.ps1`.

# Ревью N03/N19 — книги и выбор предмета сущности

База: `8619e9d56` (книги), `c825001bb` (entity pick-block),
ветка `codex/night-vanilla-02`. Оба коммита были в origin до начала ревью.
Незакоммиченное форматирование `planning/night-01/report.md` сохранено отдельно.
Эталон — локальные исходники Minecraft Java 26.3, соответствующие версии Cargo.

## Подтверждённые дефекты

### N19: поиск сущности должен учитывать доступность чанка

`ServerLevel.getEntityOrPart` обращается к visible entity lookup:
`PersistentEntitySectionManager.visibleEntityStorage` → `LevelEntityGetterAdapter`.
`World::get_entity_by_id` в Vecta включает также живые сущности скрытых чанков.
Обработчику pick-block нужен существующий `get_accessible_entity_by_id`.
Проверка дальности и removed-флага сама по себе не заменяет проверку видимости.

### N03: разрешение книги повторно захватывает инвентарь

`WrittenBookItem::use_item` разрешал страницы внутри `InventoryAccess::with_item`.
Этот closure держит inventory mutex. NBT-страница с entity source может вызвать
`CommandTextResolver::nbt_source` → `Entity::nbt_for_data_compare` →
`Player::save_command_nbt`, где тот же mutex нужен для Inventory/SelectedItem.
Разрешение страниц должно происходить вне блокировки. Снимок компонента нужен,
чтобы читать исходное содержимое инвентаря, затем отдельно применить результат.

### N03: WritableBook также вызывает общий openItemGui

Оба Java-класса — `WritableBookItem` и `WrittenBookItem` — вызывают
`Player.openItemGui`. Сервер проверяет компонент `WRITTEN_BOOK_CONTENT`.
Редактируемая книга с этим дополнительным компонентом тоже должна открывать
подписанное содержимое. Обработка только статистики для writable item пропускала
эту ветку. Обычный writable item по-прежнему не требует COpenBook от сервера.

### N03: исключение при разрешении страницы не запускает проверку её размера

В `WrittenBookContent.resolvePage` исключение возвращает исходный компонент
непосредственно из catch. Предыдущий Rust-путь проверял размер после fallback
и мог отвергнуть исходную страницу, которую Java сохраняет.

## Что сверено без обнаруженного дефекта

- Пустая рамка уже сохраняет CUSTOM_NAME через `frame_item_stack`;
  название helper отличается от Java, его поведение здесь верное.
- Заполненная рамка возвращает копию содержимого; glow-вариант делегирует
  общей реализации. Spawn egg lookup определяется ENTITY_DATA компонента item.
- `Inventory.pickSlot`, `addAndPickItem`, порядок поиска свободной панели,
  перенос вытесненного stack и перезапись при полном inventory сопоставлены
  с локальным `Inventory.java`.
- Entity range измеряется от глаз до bounding box, учитывает attribute,
  использует строгое сравнение и отвергает removed entity.
- Codec пакета и dispatch используют generated ID; запрос выполняется
  в существующем PlayerLocal packet path.

## Оставшиеся части и пределы проверки

- N19: multipart entity bodies и Avatar/includeData profile printing отсутствуют
  вместе с соответствующими реализациями. Painting/ArmorStand не реализованы;
  pick-result для них не объявляется готовым. Feature gating не добавлен:
  в текущей основе нет соответствующего enabled-features контракта.
- N03: KnowledgeBook не реализован. В Java нужны `awardRecipes` и серверная
  recipe book с выдачей рецептов клиенту; соответствующие player API в текущем
  коде не найдены. Это отдельная незавершённая система, не повод подменять выдачу
  простым ITEM_USED или набором идентификаторов.
- Text filtering использует существующее отсутствие сервиса (DUMMY pass-through).
- Дополнительно обнаружена незавершённость границы длины written-book страниц:
  `is_page_too_large` и `restricted_component_from_nbt` считают обычный serde JSON,
  а `ComponentSerialization.CODEC` Java сворачивает plain text в JSON-строку.
  Поэтому около предела 32767 возможен неверный отказ. Нужен корректный codec JSON
  для компонентов, включая вложенные значения; текущий TextComponents предоставляет
  codec NBT, а его serde-модель сохраняет объектную форму. Это не исправляется
  вычитанием фиксированного числа символов из лимита. Полная совместимость N03
  не заявляется.
- Настоящий клиент 26.3, несколько настоящих игроков и restart сервера не запускались.
  EULA не принималась. Тестовая сборка Server из готового test adapter не запускает
  серверные циклы или сетевой Minecraft-сервер.
